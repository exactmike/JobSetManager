# JobSetManager Modernization Plan — 2026-03-14

## Context

JobSetManager v0.3.2 orchestrates sets of interdependent PowerShell background jobs with dependency resolution, retry logic, result validation, and structured logging. Its only external dependency is **PoshRSJob**, which provides runspace-based parallel jobs via `Start-RSJob`/`Get-RSJob`/`Receive-RSJob`/`Remove-RSJob`.

**Goals for v1.0.0:**
1. Remove the PoshRSJob dependency — replaced by native `Start-Job` / `Start-ThreadJob`
2. Ensure PS 7.x and PS 5.1 compatibility, cross-platform readiness
3. Modernize tests to Pester v5, expand coverage
4. Expand and improve documentation and onboarding experience
5. Resolve known open issues

---

## Area 1 — Job Engine Abstraction (Remove PoshRSJob)

**Files with direct RSJob calls:**
- `Functions/Start-JSMJob.ps1` — calls `Start-RSJob`
- `Functions/Get-JSMJobCurrent.ps1` — calls `Get-RSJob`
- `Functions/Start-JSMNewJobCompletionProcess.ps1` — calls `Get-RSJob`, `Receive-RSJob`, `Remove-RSJob`
- `Functions/Start-JSMJobFailureProcess.ps1` — calls `Get-RSJob | Remove-RSJob`

**Cascading changes:**
- `Functions/Add-JSMJobAttempt.ps1` — update `ValidateSet('RSJob','PSJob')` → `ValidateSet('PSJob','ThreadJob')`
- `Functions/Initialize-TrackingVariable.ps1` — add `$script:SplitJobGroups` hashtable
- `Functions/Invoke-JSMProcessingLoop.ps1` — add `JobType` parameter
- `JobSetManager.psd1` — update description, version, metadata

### 1A — Job Type Selection

Add `JobType` parameter to `Invoke-JSMProcessingLoop`:
- `ValidateSet('PSJob','ThreadJob')`
- Default: auto-detect — use `ThreadJob` if `Start-ThreadJob` is available (PS 7+ built-in, or ThreadJob module installed on PS 5.1), else fall back to `PSJob`

### 1B — Split Job Tracking (replacing RSJob's `-Batch`)

RSJob's `-Batch` groups split sub-jobs under a parent name. Native PS jobs have no batch concept.

**Solution:** New script-scoped hashtable initialized in `Initialize-TrackingVariable`:
```powershell
$script:SplitJobGroups = @{}  # Key: JobName, Value: [string[]] of sub-job names
```

Split sub-jobs are named `{JobName}_JSMPart_{n}` (e.g., `GetUsers_JSMPart_1`).

- `Get-JSMJobCurrent`: look up both direct name matches AND all entries in `$script:SplitJobGroups`
- `Start-JSMNewJobCompletionProcess`: check batch completion via `$script:SplitJobGroups[$DefinedJob.Name]`
- `Start-JSMJobFailureProcess`: remove sub-jobs by name via the same lookup

### 1C — Parameter Mapping (RSJob → Native)

| RSJob Parameter | Start-Job / Start-ThreadJob Equivalent |
|---|---|
| `-Name` | `-Name` |
| `-ScriptBlock` | `-ScriptBlock` |
| `-ArgumentList` | `-ArgumentList` |
| `-Throttle` | Manual count check (PSJob) or `-ThrottleLimit` (ThreadJob) |
| `-Batch` | `$script:SplitJobGroups` tracking hashtable |
| `-FunctionsToLoad` | `-InitializationScript` (inject function definitions) |
| `-ModulesToImport` | `-InitializationScript` (inject Import-Module calls) |
| `-PSSnapinsToImport` | **Dropped** — deprecated, incompatible with PS 7+ |

**FunctionsToLoad injection pattern:**
```powershell
$funcDefs = foreach ($func in $FunctionsToLoad) {
    $body = (Get-Command $func -ErrorAction Stop).ScriptBlock
    "function $func {`n$body`n}"
}
$moduleImports = foreach ($mod in $ModulesToImport) {
    "Import-Module '$mod' -ErrorAction Stop"
}
$initScript = [scriptblock]::Create(($funcDefs + $moduleImports) -join "`n")
```

**Job state mapping:**

| RSJob Property | Native Job Equivalent |
|---|---|
| `.Completed -eq $true` | `.State -eq 'Completed'` |
| `.HasErrors` | `.State -eq 'Failed'` or `$j.ChildJobs[0].Error.Count -gt 0` |
| `.Error` | `.ChildJobs[0].Error` |

### 1D — Job Definition Breaking Change

Rename `StartRSJobParams` → `StartJobParams` in all job definitions, samples, and documentation. Drop `PSSnapinsToImport` key. Update README with migration guide.

### 1E — Remove PoshRSJob "Decoy Argument" Workaround

Remove the decoy first-argument workaround noted in SampleJob.ps1 — it was a PoshRSJob-specific bug.
